# 콘텐츠 스튜디오 연결

프런트엔드는 GitHub Pages에 배포됩니다. 새 계정별 분석·영상 기획 API를 켜려면 **현재 업무보고 API**의 Apps Script를 한 번 업데이트해야 합니다. 기존 캘린더 앱 스크립트가 아니라 config.js의 API_URL에 해당하는 배포를 수정하세요.

1. 현재 업무보고 API의 Apps Script 프로젝트를 열고 `Code.gs`를 이 폴더의 전체 `Code.gs` 내용으로 교체합니다.
2. 배포 → 배포 관리 → 현재 웹 앱의 수정(연필) → 버전: 새 버전 → 배포. 기존 실행 계정과 액세스 범위, 배포 URL을 유지합니다.
3. 대시보드 → 콘텐츠 스튜디오 → 새로고침. 분석과 영상 기획이 활성화됩니다.

일간 보고서·공통업무 API는 그대로 유지됩니다. 원본 콘텐츠 시트의 J:P만 영상 기획 추가·수정 대상이며 기존 셀의 서식과 다른 열은 변경하지 않습니다. 동시 수정 충돌을 검사하고, 읽기는 30초 캐시, 화면은 60초 간격으로 확인합니다. 편집 중에는 자동 새로고침을 미룹니다.

Instagram 접근 토큰은 이 기능에 필요하지 않습니다. 게시물 성과는 시트에 기록된 값을 읽고, 릴스 미리보기는 요청할 때만 Instagram에서 불러옵니다. 토큰을 HTML, JS, config.js 또는 GitHub에 넣지 마세요.

## Instagram 새 릴스 자동 수집 (API v4)

이 파일의 `Code.gs`에는 이제 **Instagram → 원본 시트 → 콘텐츠 스튜디오** 수집 경로가 포함됩니다. 이전 파일은 시트 읽기만 했습니다. 현재 대시보드가 사용하는 업무보고 API의 프로젝트에 적용해야 하며, 원본 콘텐츠 앱의 HTML은 수정할 필요가 없습니다.

1. `Code.gs` 전체를 교체하고 저장합니다. 같은 이름의 다른 함수가 중복으로 남아 있지 않은지 확인합니다.
2. 프로젝트 설정 → 스크립트 속성 → `IG_ACCESS_TOKENS`를 추가하고, 계정별 유효한 Instagram 사용자 토큰을 쉼표로 구분해 넣습니다. 토큰은 코드·대시보드·GitHub에 넣지 않습니다. API가 계정의 username을 확인하므로 토큰 순서는 무관합니다.
3. 함수 목록에서 `installInstagramSync`를 선택해 **한 번 실행**하고 권한을 승인합니다. 첫 수집과 10분 간격 트리거 설치가 이뤄집니다. 기존의 다른 트리거는 보존됩니다.
4. 배포 → 배포 관리 → 현재 업무보고 웹 앱 수정 → **새 버전** → 배포. URL을 유지하세요. 저장만 하면 이전 배포본이 계속 실행됩니다.
5. 콘텐츠 스튜디오에서 새로고침합니다. 수동 새로고침은 즉시 수집하고, 자동 확인은 60초마다 실행하며 Instagram 수집은 최소 120초 간격으로 제한합니다. 설정이 없거나 계정 연결이 실패하면 화면에 표시됩니다.

수집 대상 계정은 `dr.hongzz`, `dr.hongzz_global`, `figo_seoul`, `arskin_hongdae`입니다. 최근 50개 게시물을 조회하고 permalink로 중복을 판단해 C:H만 갱신합니다. 기존 조회수 G열, 영상 기획 J:P와 다른 열은 보존합니다. 신규 게시물의 조회수는 Instagram 기본 미디어 응답에 없으므로 공란으로 두며 0으로 표시하지 않습니다.

`contentData is not defined` 오류가 계속되면 **다른 프로젝트를 수정했거나 이전 버전이 배포 중**일 수 있습니다. 이 파일의 `contentData`, `instagramSync_` 등 하단 함수까지 모두 적용하고 새 버전으로 배포했는지 확인하세요.

## 월간 매출표 연결 (API v5)

메뉴는 콘텐츠 스튜디오 → 일간보고서 → 월간 매출표 순서입니다. 매출표는 지정한 마감 시트의 **월간요약(gid=1411519381)**만 읽으며 환자별 원장은 전송하지 않습니다. 현재 자료는 2026년 10월이므로 화면도 해당 기준월로 표시합니다.

1. 이 폴더의 최신 `Code.gs` 전체를 **현재 일일보고 API 프로젝트**에 적용합니다. API v5에는 보고서, 콘텐츠, Instagram 수집, 매출 요약 함수가 모두 포함됩니다.
2. 프로젝트 설정 → 스크립트 속성에 `REVENUE_VIEW_KEY`를 추가합니다. 충분히 긴 임의의 조회키를 직접 입력하세요. 이 값은 코드나 config.js에 넣지 말고 채팅에도 보내지 마세요.
3. 배포 관리 → 현재 업무보고 배포의 연필 → **새 버전** → 배포. 실행 계정은 해당 마감 시트를 읽을 수 있어야 합니다.
4. 대시보드 → 월간 매출표 → 위에서 정한 조회키로 열기. 조회키는 브라우저 저장소에 남기지 않고, 잠그기 또는 페이지 새로고침 시 다시 입력합니다.

수집 데이터는 A1:AF100 범위의 월간 집계뿐입니다. 총금액, 보고 건수, 일별/누적 금액, 담당자, 결제수단, 국가, 시술 포함 건수를 사용하고 일별·결제·국가별 합계와 보고 건수를 대조합니다. 보고 건수는 고유 고객 수가 아니며, 업셀 집계를 추가 매출로 해석하지 않습니다. 전월 비교나 목표 달성률은 근거 자료가 없어 표시하지 않습니다.
